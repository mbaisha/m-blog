# 13. AI 编程约定与代码规范

## 1. 目标

本规范用于保证 AI 编程时输出代码风格一致、结构清晰、可维护。

---

## 2. 通用约定

- 所有代码必须遵循项目已有结构。
- 不随意新增未规划模块。
- 不硬编码密钥。
- 不提交敏感配置。
- 不直接写死生产域名。
- 所有外部输入必须校验。
- 所有异常必须明确处理。
- 所有接口必须返回统一结构。

---

## 3. C# 后端规范

### 3.1 命名

- Controller 使用 PascalCase。
- Service 使用 PascalCase。
- DTO 使用 PascalCase。
- 方法使用 PascalCase。
- 私有字段使用 `_camelCase`。

### 3.2 Controller

- Controller 只负责接收请求和返回响应。
- 业务逻辑放在 Application Service。
- 不允许在 Controller 中直接写复杂 SQL。
- 不允许在 Controller 中直接访问文件。

### 3.3 DTO

- 请求 DTO 和响应 DTO 分离。
- 所有字段必须有明确校验。
- 不返回数据库实体原样。
- 不返回敏感字段。

### 3.4 错误处理

- 使用全局异常处理中间件。
- 错误码统一。
- 不向客户端暴露内部异常堆栈。

### 3.5 日志

- 使用 Serilog。
- 记录关键操作。
- 不记录明文密码。
- 不记录完整 Token。

---

## 4. Next.js 前台规范

### 4.1 组件

- 组件按功能拆分。
- 公共组件放入 `components/`。
- 页面组件放入 `app/`。
- 工具函数放入 `lib/`。

### 4.2 数据请求

- 封装统一 API 客户端。
- 错误统一处理。
- Loading 和 Empty 状态必须存在。

### 4.3 SEO

- 每个页面必须有 metadata。
- 文章页必须使用动态 metadata。
- Sitemap 必须自动生成。

### 4.4 样式

- 使用 Tailwind CSS。
- 不随意写全局样式。
- 保持响应式。

---

## 5. Vue3 后台规范

### 5.1 组件

- 通用组件放入 `components/`。
- 页面组件放入 `views/`。
- API 放入 `api/`。
- Store 放入 `stores/`。

### 5.2 表单

- 所有表单必须有校验。
- 删除操作必须二次确认。
- 提交操作必须有 loading。

### 5.3 权限

- 菜单按权限展示。
- 接口权限以后端为准。

---

## 6. 数据库规范

- 使用 UUID 主键。
- 使用 `timestamptz`。
- 使用 `jsonb` 存配置。
- 高频字段建索引。
- 使用迁移管理结构。
- 不手动改生产库结构。

---

## 7. 安全规范

- 不信任前端输入。
- 不信任评论。
- 不信任上传文件。
- 不信任 URL 参数。
- 不信任 Cookie。
- 所有后台接口必须鉴权。
- 所有写接口必须校验。
- 所有上传必须限制类型和大小。

---

## 8. 测试规范

### 8.1 后端

- Auth 测试。
- 文章 API 测试。
- 评论 API 测试。
- 上传 API 测试。
- 权限测试。
- 参数校验测试。

### 8.2 前台

- 首页渲染测试。
- 文章详情渲染测试。
- 评论提交测试。
- SEO Meta 测试。
- 移动端适配测试。

### 8.3 后台

- 登录测试。
- 文章管理测试。
- 评论审核测试。
- 上传测试。
- 权限测试。

---

## 9. AI 编程输出要求

当 AI 生成代码时，必须：

- 明确文件路径。
- 明确修改内容。
- 保持现有目录结构。
- 不跳过校验。
- 不跳过异常处理。
- 不跳过权限校验。
- 不生成无法运行的伪代码。
- 不硬编码密钥。
- 不输出敏感信息。

---

## 10. 验收标准

- 代码结构清晰。
- 命名一致。
- 权限完整。
- 校验完整。
- 异常完整。
- 日志完整。
- 前端页面可运行。
- 后端接口可运行。
- 数据库迁移可运行。
