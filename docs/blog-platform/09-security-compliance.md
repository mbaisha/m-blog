# 09. 安全与合规设计

## 1. 目标

保证平台在内容发布、评论互动、文件上传、后台管理过程中具备基本安全能力。

---

## 2. 认证安全

### 2.1 密码

- 密码必须使用强哈希算法。
- 禁止明文存储。
- 建议使用 `BCrypt` 或 `PBKDF2`。

### 2.2 Token

- Access Token 短期有效。
- Refresh Token 长期有效。
- Refresh Token 必须存入数据库。
- 退出登录必须使 Refresh Token 失效。
- Token 泄露后必须可撤销。

---

## 3. 权限安全

### 3.1 后端校验

所有后台接口必须由后端校验权限。

### 3.2 前端校验

前端只用于隐藏菜单和优化体验，不能作为安全边界。

---

## 4. XSS 防护

### 4.1 Markdown

- Markdown 渲染必须清洗。
- 禁止执行 `<script>`。
- 禁止危险事件属性。
- 链接协议必须白名单。

### 4.2 评论

- 评论内容必须清洗。
- 评论中禁止 HTML 脚本。
- 评论展示必须转义。

---

## 5. SQL 注入防护

- 使用 EF Core。
- 禁止 SQL 拼接。
- 查询条件必须参数化。
- 排序字段必须白名单。

---

## 6. 文件上传安全

- 校验扩展名。
- 校验 MIME。
- 限制大小。
- 重新生成文件名。
- 上传目录禁止执行脚本。
- 图片、视频、附件分目录存储。
- 不允许路径穿越。

---

## 7. CSRF 防护

### 7.1 后台管理

- 使用 JWT + SameSite Cookie 策略。
- 敏感操作可加 CSRF Token。

### 7.2 前台评论

- 验证码 + 频率限制。
- 不依赖隐藏字段作为唯一防护。

---

## 8. 审计日志

以下操作必须记录审计日志：

- 登录成功。
- 登录失败。
- 发布文章。
- 删除文章。
- 审核评论。
- 删除评论。
- 上传文件。
- 删除文件。
- 修改 SEO。
- 修改权限。

---

## 9. 隐私合规

### 9.1 评论数据

评论可能包含：

- 昵称。
- 邮箱。
- 网站。
- IP 摘要。
- 评论内容。

后台只展示必要信息。

### 9.2 IP 处理

- 不建议存储明文 IP。
- 建议存储 IP Hash。
- 后台仅展示 IP 摘要。

---

## 9.3 数据保留与隐私

- IP 不建议存储明文，建议存储 IP Hash。
- 后台仅展示 IP 摘要（前 3 段或后 3 位）。
- User-Agent 完整存储但仅供管理后台查看。
- 访问记录默认保留 30 天，过期自动删除。
- 管理员在后台可配置保留天数（最多 365 天）。
- 清理策略：定时任务每日执行，删除 `visited_at < now() - interval '{retention_days} days'` 的记录。
- 清理不删除聚合阅读数（page_views 表和业务表 view_count）。
- 后台可手动触发清理。

---

## 9.4 页脚链接安全

- ICP 备案号和公安网备案号必须指向官方验证链接。
- 社交链接、友情链接 URL 必须进行协议校验，只允许 `https://` 和 `http://`。
- 禁止 `javascript:`、`data:`、`vbscript:` 等协议。
- 友情链接自动添加 `rel="nofollow noopener"`（可选针对非信任站点）。
- 自定义区块内容进行 XSS 清理。
- 底部版权信息和备案号不可被恶意篡改。

---

## 10. 安全验收

- 未登录不能访问后台接口。
- 无权限不能执行管理操作。
- 上传非法文件被拒绝。
- Markdown 不执行脚本。
- 评论不执行脚本。
- 所有写接口有校验。
- 所有敏感操作有日志。
- Token 可刷新、可撤销。
- 密码不明文存储。
- 访问记录自动清理有效。
- 页脚链接协议校验正常。
